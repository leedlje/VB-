# VB阅读器技术方案

本方案对应 [产品设计文档](../PRODUCT_DESIGN.md)，目标平台仍为 Windows 10/11 x64。当前 TXT 阅读器已经实现阅读、书架雏形、搜索、书签、主题、排版及文件重新定位；下一大版本扩展为 TXT、EPUB、PDF 的统一书架，并将产品更名为“VB阅读器”。书籍默认引用原路径，应用保持离线，不上传或修改正文。

## 技术栈结论

**保留 Electron + TypeScript + Vite + 原生 HTML/CSS，增加 EPUB 与 PDF 专用阅读库。** Electron 已承担本地文件、窗口和 Windows 安装，现有界面无需整体重写。新格式的渲染和位置表示与 TXT 明显不同，应分别实现阅读模块，再在书架层统一入口、进度展示和书签操作。

| 层次 | 选择 | 作用 |
| --- | --- | --- |
| 桌面容器与构建 | Electron、TypeScript、Vite、esbuild | 延续主进程、预加载脚本、阅读界面的现有分层 |
| TXT | 现有文本阅读器、`iconv-lite` | 保留 UTF-8／GB18030 和字符偏移进度 |
| EPUB | `epubjs` | 解析 EPUB 元数据、目录及内容，显示可重排章节、图片和内链；使用 EPUB CFI 定位 |
| PDF | Mozilla `pdfjs-dist` | 按页渲染、文字层、页码／缩放及可搜索文本；打包本地 worker |
| 本地记录 | 版本化 JSON 状态文件，单独的封面缓存目录 | 存书架元数据、设置和各格式位置；不缓存整本正文 |
| 测试与分发 | Node 测试、Playwright/Electron 窗口测试、electron-builder/NSIS | 覆盖三种格式及旧版升级，交付离线 x64 安装包 |

依赖在实现时选相互兼容的稳定版本并锁定。当前书架只做本地文件元数据、排序、筛选和书名搜索，JSON 仍足够；若以后加入跨书全文索引或大量复杂查询，再评估 SQLite。版本和现有脚本见 [package.json](../package.json)。

## 数据与应用边界

当前 [状态存储](../src/main/state.ts) 使用 `version: 3`，以文件路径管理 TXT 记录。新版本将书架记录升级为稳定的 `bookId`，记录格式、规范化路径、书名、作者、封面缓存键、导入／最近阅读时间、文件变更信息以及按格式区分的位置和书签。另由路径建立去重索引；同一路径重复导入复用记录，重新定位只更换路径，不改变 `bookId`。

位置采用可区分的类型：TXT 保存字符偏移，EPUB 保存 CFI（必要时附章节标识），PDF 保存页码和页内相对位置。书架统一显示进度百分比，但不能把百分比作为唯一恢复位置。格式专用阅读模块负责定位、搜索和书签；共用书架、错误提示、设置和状态持久化。

状态格式从 `version: 3` 升级时，须兼容读取已有 `version: 1`、`version: 2` 和 `version: 3` 数据，迁移 TXT 的路径、编码、进度、书签、最近阅读时间及全局字号、主题、行距、正文宽度。迁移失败保留旧状态文件并给出可恢复的错误；新状态使用临时文件写入并替换。封面缩略图放在独立缓存目录，缺失或损坏时可以重新生成；状态文件不存整本正文或整页 PDF 图像。

继续由主进程控制文件选择、路径验证和磁盘读写，渲染进程经预加载脚本使用受限 API。三种格式的内容只从用户已导入的本地文件读取；大 PDF 的读取与页面渲染应按需进行，避免一次性将所有页面或整本搜索索引放入界面内存。EPUB 内容按不可信文档处理：禁止书内脚本和远程资源，限制外链与导航，保持 Electron 的沙箱、`contextIsolation` 和 `nodeIntegration: false`。

## 大版本实施顺序

### 1. 统一书架

扩展系统文件对话框为多选 TXT、EPUB、PDF。导入流程先验证格式并读取必要元数据，再为每本书建立或复用记录；一本文件损坏不应中断其他文件的导入。标题、作者和封面优先取文件自带信息；缺失时使用文件名、空作者及默认封面。EPUB 封面来自书内资源；PDF 可异步生成首页缩略图。书架按最近阅读或书名排序，按格式筛选，并对书名做本地搜索。

移出书架只删除记录及相应封面缓存，不删除原文件。原文件移动后可沿用现有重新定位流程保留 `bookId` 与阅读记录，但需验证目标文件格式并处理路径冲突。统一书架上线时自动纳入旧 TXT 记录，升级后可直接继续阅读。

### 2. EPUB 阅读

使用 `epubjs` 的书脊顺序、目录和呈现能力显示可重排正文、图片与书内链接；阅读位置与书签保存为 CFI，排版改变后按 CFI 恢复。章节目录用于跳转，文内搜索按章节逐步查找并可取消旧查询，结果返回可跳转的 CFI。书架进度从 EPUB 位置映射为展示用百分比。

导入时区分可重排 EPUB、固定版式和加密／DRM 文件；不支持的文件显示具体原因，不创建半成品记录。书内脚本默认禁用，正文中的外部链接和资源请求不自动访问网络。实现前用真实中文、英文、带图片和内链的样本验证 `epubjs` 的兼容性与 CFI 恢复。

### 3. PDF 阅读

使用 `pdfjs-dist` 的本地 worker 按需渲染可见页面，提供翻页、页码跳转、缩放、适合页面和适合宽度。保存页码及页内相对位置；书签同样按页定位，缩放或窗口变化后可恢复到合理位置。PDF 保持原版式，不应用 TXT／EPUB 的字号和行距设置。

按需提取页面文字层做文内搜索，结果包含页码及页内位置。扫描版仍可显示图像页面；无文字层时说明无法搜索文字，不尝试 OCR。损坏、加密或无法解码的 PDF 要给出提示，书架和其他书籍继续可用。

### 4. 产品更名

将应用界面、窗口标题、程序文件名、安装程序名称、系统快捷方式和 [README](../README.md) 统一改为“VB阅读器”。保留现有 `appId` 或等效安装标识，确保 NSIS 将新版识别为旧版升级；应用名称改变可能使 Electron 的默认 `userData` 目录变化，因此需要固定数据路径或执行一次旧目录迁移。升级验证必须使用真实旧版安装与状态，确认原书架、TXT 进度、书签和设置可见。

## 验证与交付

- **书架与迁移**：混合批量导入、重复路径、元数据缺失、排序／筛选／书名搜索、移出与重新定位；验证 TXT 旧状态从各历史版本迁移且原文件未被改动。
- **EPUB**：目录、图片、内链、搜索、书签、排版后与重启后的 CFI 恢复；固定版式、DRM 和损坏文件有明确反馈。
- **PDF**：页码、缩放、适合页面／宽度、位置恢复、逐页书签和文字层搜索；扫描版可读但说明不能搜索文字。
- **安全与性能**：恶意 EPUB 的脚本及远程请求不能执行；常见长篇 TXT、EPUB、PDF 的导入、切换和搜索保持窗口响应。
- **升级安装**：旧版安装包覆盖升级到 VB阅读器后，Windows 入口名称正确，原记录和设置仍可访问。

每一阶段完成后运行 `npm run verify` 和真实 Electron 窗口验收；最终运行 `npm run dist:win` 并在 Windows 10/11 x64 验证离线安装及升级。拖入文件、文件关联、跨书搜索、OCR 和云同步留待后续版本。
