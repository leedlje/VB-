# Windows 本地电子书阅读器技术方案

本方案对应 [产品设计文档](../PRODUCT_DESIGN.md)，面向 Windows 10/11 x64。TXT 阅读 MVP 已实现；下文先记录现有技术栈，再说明下一阶段各项功能的实现方向。应用继续离线运行，不要求账号，不上传或改写用户的书籍正文。

## 技术栈结论

**继续使用 Electron + TypeScript + Vite 和原生 HTML/CSS。** 最近阅读、当前 TXT 文内搜索、书签与主题都能在现有单窗口应用中逐项完成，无需重写桌面容器或引入 React。当前文件内搜索不需要全文索引服务；本地元数据规模也暂不需要数据库。若以后支持大量书籍的跨书搜索或复杂管理，再评估 SQLite 等方案。

| 层次 | 当前选择 | 下一阶段用途 |
| --- | --- | --- |
| 桌面容器 | Electron | 窗口、文件对话框、本地读写和应用生命周期 |
| 语言与界面 | TypeScript、原生 HTML/CSS | 阅读视图、最近阅读列表、搜索、书签和主题 |
| 构建 | Vite（界面）、esbuild（主进程与预加载脚本） | 沿用现有构建流程 |
| TXT 解码 | `iconv-lite` | 保持 UTF-8 默认、手动切换 GB18030 |
| 本地状态 | `userData/reader-state/state.json` | 扩充逐文件记录和全局外观设置 |
| 测试与分发 | Node 测试、Playwright/Electron 窗口测试、electron-builder/NSIS | 回归测试与 Windows x64 安装包 |

版本与实际脚本以 [package.json](../package.json) 和锁文件为准。现有代码按 [主进程](../src/main/index.ts)、[状态存储](../src/main/state.ts)、[预加载脚本](../src/preload/index.ts)、[阅读界面](../src/renderer/index.ts) 和 [共享类型](../src/shared/types.ts) 分层。

## 保留的基础能力

文件选择、解码和状态读写继续由主进程处理；阅读界面通过预加载脚本暴露的定向 API 访问这些能力。保持 `contextIsolation`、沙箱和关闭 `nodeIntegration`，新增书架或书签操作也使用单独的受限 IPC 接口。TXT 始终按纯文本显示，不把文件内容当成 HTML。

现有进度以正文的 JavaScript 字符串偏移保存。新功能共用这一 TXT 定位方式：跳转搜索结果或书签时定位到对应偏移，字号或主题改变时先保留当前可见位置再重新排版。文件内容变化、重新解码或偏移越界时，限制到有效范围并明确处理旧位置可能不再精确的情况。

## 下一阶段实施顺序

### 1. 最近阅读与简易书架

在现有逐文件记录中增加最近阅读时间和正文长度，用于排序及显示上次保存的进度。列表展示文件名、最近阅读时间和进度；选择条目时重新检查原文件并打开。文件丢失或不可读时显示提示，允许用户移除记录。移除操作只删除应用状态中的该条记录，不删除磁盘上的 TXT；若移除的是当前阅读文件，应结束该文件的自动进度写入，避免滚动立即重建记录。再次明确打开该文件时可建立新记录。

### 2. 当前 TXT 文内搜索

利用已加载的正文做普通文本匹配，记录结果的字符偏移，显示命中数量及当前序号，并支持上一个、下一个和无结果提示。搜索结果是临时界面状态，不写进本地记录。跳转时沿用现有偏移定位；高亮应保持正文文本节点和进度偏移稳定，可使用 `Range` 配合 CSS Custom Highlight API。对较大文件分批查找并允许新查询取消旧任务，避免长时间占用界面线程。

### 3. 书签

每本文件分别保存书签 ID、正文字符偏移和创建时间；列表可以用位置或进度标识书签，不把正文片段复制进状态文件。添加、跳转和删除都通过当前文件记录完成。跳转前检查偏移有效性；如果原文件发生变化，定位到可用位置并提示可能存在偏差。

### 4. 阅读外观

在现有字号设置之外加入明亮、深色和护眼主题，使用 CSS 变量统一正文、背景、工具栏与交互状态颜色。主题作为全局设置保存；切换时保留当前阅读位置。行距等设置等用户反馈明确后再增加，避免提前扩展状态结构。

每项功能独立交付，并回归现有 TXT 打开、编码切换、字号调整和重启恢复能力。

## 状态升级与可靠性

当前状态文件使用 `version: 1`。扩展数据结构时应显式迁移已有记录，保留原路径、编码、偏移、字号和最近文件；不能因为版本变化把老用户的进度重置。新增字段为缺失值提供默认值。继续使用临时文件写入并替换正式状态文件，处理状态损坏和写入失败；正文仍只保存在用户原文件中。

文件路径仍是 TXT 记录的身份依据。最近阅读时间在实际阅读时更新；列表中的正文长度只是上次打开时的缓存，文件变化后重新计算进度。以后若实现 EPUB 或 PDF，再为不同格式分别设计内容模型和位置表示，不直接套用 TXT 字符偏移。

## 测试与交付

- **状态迁移**：旧版进度与字号保持不变；新字段缺失、损坏状态文件和写入失败时可恢复或给出提示。
- **最近阅读**：排序、进度显示、文件丢失、移除记录及移除当前文件后不自动重建；确认原 TXT 未被修改。
- **搜索与书签**：中文匹配、无结果、前后跳转、逐文件隔离、删除、重启恢复，以及文件内容变化后的越界处理。
- **阅读外观**：主题持久化、切换前后位置稳定，并回归字号、编码和长行换行。
- **窗口验证**：每项功能通过自动化测试后，在真实 Electron 窗口完成关键操作；继续运行 `npm run verify`，打包时再运行 `npm run dist:win`。

下一阶段仍交付 Windows 10/11 x64 离线 NSIS 安装包。EPUB、PDF、批注、朗读、云同步和自动章节识别目前只作为后续候选方向，不进入上述实施范围。
