# Windows 本地电子书阅读器技术方案

本方案对应 [产品设计文档](../PRODUCT_DESIGN.md)，面向 Windows 10/11 x64。TXT 阅读、最近阅读、文内搜索、书签和主题已实现；下一小版本依次完善文件重新定位、键盘操作和阅读排版。应用保持离线运行，不要求账号，不上传或修改用户的 TXT 正文。

## 技术栈复核

**继续使用 Electron + TypeScript + Vite + 原生 HTML/CSS。** 新需求都属于现有单窗口阅读器的文件操作或界面交互，当前 JSON 状态文件也足以存放少量阅读记录和设置。无需为本次迭代引入数据库、服务端或前端框架。

| 层次 | 现有选择 | 本次用途 |
| --- | --- | --- |
| 桌面容器 | Electron | 文件选择窗口、应用生命周期和受限 IPC |
| 界面与语言 | TypeScript、原生 HTML/CSS | 快捷键、面板交互、行距与正文宽度控制 |
| 构建 | Vite（界面）、esbuild（主进程与预加载脚本） | 沿用现有构建流程 |
| TXT 解码 | `iconv-lite` | 重新定位时按原记录编码验证并打开新路径 |
| 本地状态 | `userData/reader-state/state.json` | 路径迁移与新增全局排版设置 |
| 测试与分发 | Node 测试、Playwright/Electron 窗口测试、electron-builder/NSIS | 回归验证与 Windows x64 安装包 |

依赖版本与命令以 [package.json](../package.json) 和锁文件为准。现有代码分为 [主进程](../src/main/index.ts)、[状态存储](../src/main/state.ts)、[预加载脚本](../src/preload/index.ts)、[阅读界面](../src/renderer/index.ts) 和 [共享类型](../src/shared/types.ts)。

## 当前实现基础

当前状态文件为 `version: 2`：逐文件保存路径、编码、字符偏移、正文长度、修改时间、最近阅读时间和书签；全局保存字号与主题。TXT 正文只在打开时读取，书签和进度使用 JavaScript 字符串偏移定位。搜索基于当前加载的正文，不需要额外的全文索引。

继续由主进程处理磁盘读写，阅读界面只通过预加载脚本的定向 API 请求操作。保持 `contextIsolation`、沙箱和关闭 `nodeIntegration`；新增重新定位接口应验证请求来源和参数。TXT 内容仍按纯文本渲染。

## 下一小版本实施顺序

### 1. 重新定位文件

从最近阅读中的某条旧记录发起操作，由主进程打开 TXT 文件选择窗口。用户取消时不改状态。选定新路径后，先确认它是可读 TXT，并用旧记录的编码尝试读取；验证成功后再迁移记录，保留编码、进度、书签和最近阅读时间，同时更新路径、正文长度、修改时间及关联的 `lastFile`。当前正在阅读的若是该记录，也要切换到新路径，避免后续保存重新写回旧路径。

路径以现有规范化规则比较。若新路径已有另一条阅读记录，先提示冲突并拒绝静默覆盖；无效文件或持久化失败时保留旧记录。迁移只修改应用状态，不移动、重命名或写入用户 TXT。使用旧记录的长度和修改时间判断内容可能变化，并提示旧进度、书签可能偏移；这些元数据不能证明两份文件内容完全相同。打开新文件时按现有规则限制越界的跳转位置。

### 2. 键盘操作

在阅读窗口内统一处理 `Ctrl+O`、`Ctrl+F`、`F3`、`Shift+F3` 和 `Esc`，分别复用已有打开文件、聚焦搜索、结果跳转和关闭当前搜索或侧栏的动作。使用窗口内按键事件，不注册系统全局快捷键。仅拦截明确匹配的组合；输入法合成期间和输入框的普通编辑键保持原行为。关闭面板后恢复合理的焦点，按钮仍可完成所有主要操作。

### 3. 阅读排版设置

在现有字号和主题之外增加有上下限的行距与正文宽度选项，作为全局设置保存。用 CSS 变量控制 `line-height` 与正文最大宽度，并在窄窗口限制实际宽度，使正文、工具栏和侧栏不相互遮挡。调整设置或窗口宽度变化时，先记录当前可见正文的字符偏移，布局完成后再定位到附近；连续拖动或缩放时对保存与重定位做适当节流。

每项功能单独完成后，都回归 TXT 打开、编码切换、最近阅读、搜索、书签、主题、进度保存和启动恢复。

## 状态升级与边界

新增排版字段时将状态格式从 `version: 2` 升级，显式迁移现有 `version: 1` 和 `version: 2` 文件；缺失的新字段使用当前排版默认值。迁移必须保留已有路径、编码、进度、书签、字号、主题和最近文件。重新定位应作为一次记录变更完成，在写入失败时保留原记录，不能留下只改了一半的路径或索引。

当前字符偏移适用于 TXT；文件内容变更时只能尽量恢复到附近位置，不能承诺精确对应。拖入文件、资源管理器关联打开、大文件优化，以及 EPUB/PDF 等其他格式仍是后续候选，不纳入本次实现。

## 测试与交付

- **重新定位文件**：成功迁移后重启仍从新路径恢复，编码、进度和书签保留；覆盖取消、错误文件、路径冲突、写入失败、当前文件迁移和正文变化提示，并确认原 TXT 未修改。
- **键盘操作**：覆盖所有组合键、搜索无结果、`Esc` 关闭面板、输入框编辑及输入法合成；验证按钮与快捷键效果一致。
- **阅读排版**：行距和宽度即时生效并在重启后保留；测试字号、主题、窗口缩放、窄窗口和较长 TXT 下的位置稳定与正文可见性。
- **回归**：自动化测试与真实 Electron 窗口测试都通过；每次交付运行 `npm run verify`，制作安装包时运行 `npm run dist:win`。

交付目标继续是 Windows 10/11 x64 离线 NSIS 安装包。
